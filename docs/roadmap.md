# 로드맵

일정은 기한 없는 **범위 단위 마일스톤**으로 관리한다. 완료 기준을 채우면 바로 닫고 다음으로 넘어간다.
진행 절차는 `.claude/skills/milestone`에 있다.

## 마일스톤을 닫는 조건
1. 아래 "완료 기준 E2E"가 통과한다.
2. CI가 녹색이다.
3. `design-review` 점검 결과의 문제를 고쳤다.
4. 사용자가 확인하면 `m<n>` 태그를 단다.

## M1 — 회원·인증·판매자 입점
- [ ] auth: 가입, 이메일 인증, 로그인 화면, 잠금, OAuth2 클라이언트 3개, `client_credentials`, 키 저장(R7)
- [ ] member: 프로필, 배송지, 입점 신청·심사, 판매자 정지, 탈퇴
- [ ] notification: 이메일 발송 기반, 중복 방지
- [ ] BFF 로그인·로그아웃·토큰 갱신(R8), 앱 3개 로그인 화면
- [ ] gateway 경로별 역할 검사, 레이트 리밋(NFR-5)
- 관련 요구사항: ACC-1~4, SEL-1~3, NTF-1(가입), NFR-5, NFR-6

**완료 기준 E2E**: 가입 → 인증 메일(Mailpit) → 로그인 → 입점 신청 → 관리자 승인 → 토큰 갱신 후 판매자 앱 진입. 승인 전에는 판매자 API가 403이다.

## M2 — 상품·재고·검색 기본
- [ ] file: 업로드, 검사, 썸네일, 첨부 확정, 정리
- [ ] catalog: 카테고리, 상품, SKU, 재고 조정, 판매 중지·재개, 관리자 제재, 판매자 정지 반영
- [ ] search: ES 커스텀 이미지(R10), 색인, 기본 검색·필터·정렬
- [ ] 판매자 상품 관리 화면, 구매자 상품 목록·상세·검색 화면
- 관련 요구사항: CAT-1~5, SRC-1, SRC-3

**완료 기준 E2E**: 판매자가 이미지와 SKU로 상품을 등록하면 몇 초 안에 구매자 검색에 나온다. 판매를 중지하면 검색에서 빠진다.

## M3 — 장바구니·주문·결제
- [ ] order: 장바구니, 주문 생성(가격 재확인, 멱등), 하위 주문, 만료
- [ ] catalog: 재고 예약·확정·해제, 동시성(CAT-4)
- [ ] payment: 토스 결제위젯 연동(R9), 금액 대조, 승인 타임아웃 처리, 보상 취소, 원장
- [ ] 멱등성 키 필터(NFR-2), 동기 호출 서킷 브레이커(NFR-4)
- [ ] 주문서, 결제, 주문 목록·상세 화면
- 관련 요구사항: ORD-1~4, PAY-1, PAY-3, PAY-4, NFR-1~4

**완료 기준 E2E**: 판매자 둘의 상품을 한 번에 주문하고 토스 테스트 결제로 승인하면, 주문이 `PAID`가 되고 하위 주문 둘이 생긴다. 재고 부족 주문은 취소되고 예약이 풀린다. 결제하지 않은 주문은 만료된다. 만료 직후 승인된 결제는 자동 취소된다.

## M4 — 배송·클레임
- [ ] fulfillment: 발주 확인, 발송, 배송 시뮬레이터, 구매확정(자동 포함, ShedLock)
- [ ] 클레임: 발송 전 취소, 반품, 교환, 거부·중재
- [ ] payment: 부분취소 환불(PAY-2)
- [ ] notification: 발송, 클레임 결과 알림, 인앱 알림
- [ ] 판매자 주문·배송·클레임 화면, 구매자 배송 조회·클레임 화면
- 관련 요구사항: FUL-1~3, CLM-1~3, PAY-2, NTF-1~2

**완료 기준 E2E**: 발송 → 배송 완료 → 반품 신청 → 판매자 승인 → 부분 환불 → 재입고. 다른 하위 주문은 7일 뒤(시간 조작) 자동 구매확정된다.

## M5 — 쿠폰·리뷰·정산·검색 고도화
- [ ] promotion: 쿠폰 정책, 선착순 발급(Redis), 주문 예약·사용·복원
- [ ] review: 작성 자격, 리뷰, 답글, 숨김, 별점 요약
- [ ] settlement: 정산 대상, 수수료율, 주간 배치(멱등), 지급 처리
- [ ] search: 자동완성, 별점·판매량 랭킹 반영
- 관련 요구사항: PRM-1~3, REV-1~3, STL-1~4, SRC-2

**완료 기준 E2E**: 선착순 쿠폰을 받아 주문에 적용하고, 구매확정 후 리뷰를 쓰면 검색 결과의 별점이 바뀐다. 정산 배치를 두 번 돌려도 정산 금액이 같다.

## M6 — 운영 성숙도
- [ ] 관리자 백오피스: 운영 지표, 감사 로그 조회, DLT 재처리(ADM-4, ADM-5)
- [ ] k6 부하 테스트(NFR-9)와 성능 개선 기록(README 표)
- [ ] 장애 주입: Kafka 중지, DB 지연, 외부 PG 지연 상황에서 정합성 확인
- [ ] 대시보드와 알림 규칙(NFR-10)
- [ ] 개인정보 마스킹·감사 로그 점검(NFR-7, NFR-8), OWASP Top 10 점검
- [ ] 관리자 2단계 인증(TOTP)
- [ ] 운영 런북(장애 유형별 대응 절차)

**완료 기준 E2E**: k6 시나리오에서 NFR-9 목표를 만족한다. Kafka를 1분간 중지했다가 다시 띄워도 이벤트 유실이 없고, Saga가 끝까지 진행된다.

# 0004. 코레오그래피 Saga
- 상태: 승인
- 날짜: 2026-10-16

## 맥락
주문은 재고 예약(catalog), 쿠폰 예약(promotion), 결제(payment), 배송 생성(fulfillment)에 걸친다. 분산 트랜잭션(2PC)은 쓰지 않는다.

## 결정
- 중앙 오케스트레이터 없이 각 서비스가 이벤트에 반응하는 코레오그래피로 구현한다.
- 주문 상태는 order가 소유한다. 실패 시 order가 `OrderCancelled`를 내고, 각 서비스가 자기 보상(예약 해제, 쿠폰 복원, 결제 취소)을 한다.
- 결제 승인과 주문 만료가 겹치는 경우는 payment가 승인 후 전액 취소로 보상한다.
- 흐름 전체는 [messaging.md](../architecture/messaging.md)에 시퀀스로 적고, 이 문서를 원본으로 유지한다.

## 결과
- 좋아지는 점: 서비스 사이 결합이 약하다. 단일 장애 지점이 없다.
- 감수하는 점: 흐름이 여러 서비스에 흩어진다. 그래서 시퀀스 문서, 분산 트레이스, Saga 단계별 지표로 보완한다.
- 단계가 크게 늘면(예: 결제 수단 여러 개를 섞는 결제) 오케스트레이션 도입을 다시 검토한다.

## 검토한 대안
- 오케스트레이션(order가 명령 이벤트를 보내고 응답을 받음): 흐름이 한 곳에 보인다. 하지만 지금 단계 수에서는 order에 로직이 몰리고, 명령·응답 토픽이 두 배가 된다.

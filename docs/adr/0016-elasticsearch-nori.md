# 0016. Elasticsearch는 nori를 더한 커스텀 이미지, 한국어 필드는 mixed 분석기 하나로 색인·검색한다
- 상태: 승인
- 날짜: 2026-10-19

## 맥락
SRC-1은 한국어 형태소 분석(nori)을 요구한다. 공식 `elasticsearch` 이미지에는 nori 플러그인이 없다(R10).
상품명은 띄어쓰기 없이 붙여 쓰는 일이 많다(`무선블루투스이어폰`, `반팔티셔츠`). 부분어로도 찾혀야 하고, 띄어 쓰든 붙여 쓰든 같은 상품이 나와야 한다. 복합어 검색이 관계없는 상품까지 넓게 잡으면 안 된다(`사과즙`으로 `착즙기`가 나오면 안 된다).

## 결정
- `infra/elasticsearch/Dockerfile`에서 공식 이미지(ADR 0009의 태그)에 `elasticsearch-plugin install --batch analysis-nori`를 더한다. 플러그인은 ES와 같은 버전을 받는다. 이미지 이름은 `openmarket/elasticsearch:<ES 버전>`이고 `search` profile이 빌드한다.
- 한국어 텍스트 필드는 분석기 하나로 색인하고 검색한다: `nori_tokenizer`(`decompound_mode: mixed`) + `nori_part_of_speech` + `nori_readingform` + `lowercase`. 복합어 원형과 부분어를 같은 위치에 둔다.
- 검색어는 `match`의 `operator: and`로 묶는다. 같은 위치의 원형과 부분어는 동의어처럼 하나로 묶이므로, 원형이 없는 문서(띄어 쓴 `사과 즙`)도 찾는다.
- 인덱스 매핑의 원본은 search 서비스 코드에 둔다(M2 search 색인 PR). search의 Testcontainers 테스트도 같은 Dockerfile로 이미지를 만들어 쓴다.

## 결과
- 좋아지는 점
  - 실측(2026-10-19, 상품명 6~7개): `이어폰`이 `무선블루투스이어폰 화이트`를, `티셔츠`·`반팔 티셔츠`가 `남성용 반팔티셔츠`를, `버즈3`이 `삼성 갤럭시 버즈3 프로`를 찾았다. `착즙기 녹즙기`는 어느 검색어에도 나오지 않았다.
  - `사과즙`은 `유기농 사과즙 100ml`(3.02)과 `사과 즙 원액`(2.06)을 모두 찾고, 원형이 맞는 상품을 위에 둔다.
  - 이미지 크기는 공식 이미지보다 약 10MB 크다. 메모리는 1.5GB로 R6 실측과 같다.
- 감수하는 점
  - 이미지를 빌드할 때 Elastic 저장소에서 플러그인을 내려받는다. 처음 한 번은 인터넷이 필요하다.
  - 영문·한글 표기 차이(`IPHONE`과 `아이폰`)는 잇지 않는다. 동의어·사용자 사전은 두지 않는다. 필요해지면 M5 검색 고도화에서 검토한다.
  - ES 태그를 올리면 nori도 함께 올라간다. ADR 0009 표와 Dockerfile의 `ES_VERSION`을 같이 고친다.

## 검토한 대안
- **기동 때 플러그인 설치(entrypoint)**: 이미지를 빌드하지 않지만 기동할 때마다 내려받는다. 오프라인에서 뜨지 않는다.
- **색인 `mixed`, 검색 `discard`**: 흔히 쓰는 조합이지만 검색어에 원형이 없어서, `사과즙`에서 `사과 즙 원액`(2.06)이 `유기농 사과즙 100ml`(1.59)보다 위로 갔다.
- **색인·검색 모두 `discard`**: 원형이 색인에 없어 위와 같은 순서가 됐다(1.95, 1.46).
- **`standard` + n-gram**: 형태소를 모르고 색인이 커진다. SRC-1의 nori 요구를 채우지 못한다.

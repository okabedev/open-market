# 0005. 자체 OAuth2/OIDC 인가 서버
- 상태: 승인
- 날짜: 2026-10-16

## 맥락
구매자, 판매자, 관리자 세 앱이 같은 계정 체계를 쓴다. 서비스는 표준 토큰(JWT)으로 인가해야 하고, 서비스 사이 호출도 인증해야 한다.

## 결정
- Spring Authorization Server로 `auth` 서비스를 직접 만든다. 계정, 자격 증명, 역할, OAuth2 클라이언트, 서명 키를 소유한다.
- 사용자 로그인은 Authorization Code + PKCE, 서비스 사이 호출은 `client_credentials`로 한다.
- 프로필은 member가 소유하고, `accountId`를 공유 식별자로 쓴다.

## 결과
- 좋아지는 점: OAuth2/OIDC 흐름을 직접 구현해 보여줄 수 있다. 가입, 잠금, 역할 부여를 도메인 이벤트와 자연스럽게 엮는다.
- 감수하는 점: 보안 구현 책임이 커진다. 키 회전, 토큰 폐기, 잠금 정책을 직접 테스트해야 한다.

## 검토한 대안
- Keycloak: 기능은 풍부하지만 도메인 이벤트(입점 승인 → 역할 부여) 연동에 커스터마이징이 필요하고, 메모리를 많이 쓴다.
- member 서비스가 JWT 직접 발급: 단순하지만 표준 흐름(PKCE, 토큰 갱신·폐기, OIDC)을 다시 구현하게 된다.

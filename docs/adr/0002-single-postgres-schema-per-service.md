# 0002. PostgreSQL 하나, 서비스별 스키마
- 상태: 승인
- 날짜: 2026-10-16

## 맥락
MSA에서는 서비스가 자기 데이터를 소유해야 한다. 그런데 로컬에서만 돌리는 비용 0 환경이라 DB 인스턴스를 서비스마다 띄우면 메모리 부담이 크다.

## 결정
- PostgreSQL 인스턴스 하나, 데이터베이스 하나에 서비스별 스키마와 전용 계정을 둔다.
- 각 계정은 자기 스키마에만 권한이 있다. 다른 스키마를 조인하거나 읽지 않는다.
- 스키마 변경은 서비스별 Flyway로만 한다.

## 결과
- 좋아지는 점: 컨테이너 하나로 자원을 아낀다. 권한으로 소유권 경계를 강제한다. 나중에 스키마를 다른 인스턴스로 옮기기 쉽다.
- 감수하는 점: 인스턴스 장애는 모든 서비스에 영향을 준다. 커넥션 수를 서비스 합계로 관리해야 한다.
- Debezium은 인스턴스 하나에서 모든 outbox를 읽으므로 커넥터가 하나면 된다([0003](0003-outbox-debezium.md)).

## 검토한 대안
- 서비스별 인스턴스: 경계는 가장 확실하지만 로컬 메모리가 부족하다.
- 폴리글랏 저장소 적극 혼용: 학습 범위는 넓어지지만 운영 부담이 크다. Redis와 Elasticsearch만 목적이 분명한 곳에 쓴다.

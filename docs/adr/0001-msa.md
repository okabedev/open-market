# 0001. MSA와 Spring Cloud 인프라
- 상태: 승인
- 날짜: 2026-10-16

## 맥락
오픈 마켓은 회원, 상품, 주문, 결제, 배송, 쿠폰, 리뷰, 정산, 검색처럼 변경 주기와 부하 특성이 다른 영역으로 나뉜다. 이 프로젝트는 풀스택 포트폴리오이며, 분산 환경의 정합성, 장애 격리, 관측성을 직접 다루는 것이 목표에 들어 있다.

## 결정
- 바운디드 컨텍스트 단위로 core 서비스 9개(member, catalog, order, payment, fulfillment, promotion, review, settlement, search)를 둔다.
- 인프라 서비스로 gateway(Spring Cloud Gateway), discovery(Eureka), config(Spring Cloud Config), auth, file, notification을 둔다.
- 서비스 사이 상태 변경은 이벤트로, 조회만 동기 호출로 한다.
- 서비스 이름은 고유 명사 한 단어로 짓고 `-service` 접미사를 붙이지 않는다.

## 결과
- 좋아지는 점: 영역별 독립 배포·확장 구조, 장애 격리, 이벤트 기반 설계 경험을 코드로 보여줄 수 있다.
- 감수하는 점: 분산 트랜잭션(Saga), 이벤트 스키마 관리, 로컬 자원 사용량, 운영 복잡도가 커진다. 로컬 메모리는 [risks.md](../architecture/risks.md) R6에서 실측한다.
- 세분화를 서비스 12개 이상으로 하지 않았다. 장바구니와 주문, 배송과 클레임처럼 같은 트랜잭션 경계를 자주 공유하는 것은 한 서비스에 둔다.

## 검토한 대안
- 모듈러 모놀리스: 구현과 운영이 가장 단순하다. 하지만 분산 환경을 다루는 목표에 맞지 않아 택하지 않았다.
- 도메인별 세분화(12개 이상): 서비스 사이 이벤트와 Saga 단계가 늘고, 로컬 자원 부담이 커진다.
